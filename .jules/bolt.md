## 2024-04-11 - Caching Computationally Expensive UI Engines Without `Send`
**Learning:** `Capstone` disassembly engine is extremely expensive to initialize on every memory read event (caused massive frontend UI stutters/bottlenecks). However, it does not implement the `Send` trait, making it tricky to use across standard threads. Because `eframe::App` instances run exclusively on the main UI thread in this setup, it is completely safe and highly performant to cache the `Capstone` instance directly within the `StealthApp` struct state.
**Action:** Always cache expensive parsing/disassembly engines (like Capstone) in the persistent app state rather than re-instantiating them in the hot rendering or event-processing loops, especially when memory is read frequently. Even if a struct isn't `Send`, it can safely reside in the eframe application state.
