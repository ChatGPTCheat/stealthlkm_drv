## 2025-01-20 - Avoid `format!` in hot UI/Network loops in Rust eframe apps
**Learning:** In eframe/egui apps, the UI render loop and associated network response parsing loops are executed incredibly frequently (e.g., every 50ms or per frame). Calling `format!` inside loops (especially for large payloads like memory hex dumps or disassembler output) incurs massive overhead due to continuous heap allocations for the intermediate strings.
**Action:** Always pre-allocate a `String::with_capacity(...)` and use `write!(&mut str, ...)` from `std::fmt::Write` instead of `str.push_str(&format!(...))` to format data directly into the target string buffer, saving per-iteration allocations. Use import aliasing (`use std::fmt::Write as FmtWrite;`) to avoid conflicts if `std::io::Write` is also in scope.
