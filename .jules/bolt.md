## 2024-06-25 - Avoid Expensive Re-initialization in Polling Loops
**Learning:** In the Rust GUI application, the `disassemble_arm64` function was repeatedly instantiating `Capstone::new()` for every disassembly request. This was particularly inefficient because it happened inside the immediate mode GUI event loop polling (e.g., when a memory read result was processed). The `Capstone` struct does not implement `Send`, but since it is accessed in the `eframe::App`'s update loop which runs on the main UI thread, it is safe and highly beneficial to initialize it once in `StealthApp::new` and store it in the application state.
**Action:** Always cache expensive initialization objects (like disassembly engines) in the main application state if they are going to be used repeatedly during UI updates or event processing in immediate mode GUIs. Ensure the cached object handles threading rules correctly (e.g., accessed only by the main thread).
