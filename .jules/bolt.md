## 2025-02-14 - Capstone Initialization Performance
**Learning:** `Capstone::new().build()` is computationally expensive and should never be invoked repeatedly within a hot loop, UI rendering cycle, or per network request handling path. In the Rust GUI component, it was previously being instantiated repeatedly per disassembly call, causing an unnecessary performance drag. Furthermore, although `Capstone` is not `Send`, the `eframe::App` design in this project allows retaining it safely as component state (`cs: Result<capstone::Capstone, capstone::Error>`) within `StealthApp`, keeping instantiation costs to startup time only.
**Action:** Always cache stateful libraries like disassemblers or language parsers on initialization when used within UI loops or frequent handlers.
