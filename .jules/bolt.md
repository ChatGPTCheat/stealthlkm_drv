## 2024-06-18 - Optimized string formatting and Capstone allocation in GUI hot paths
**Learning:** In Rust GUI rendering loops (`eframe`/`egui`), using `format!` inside hot loops (like hex dumps or disassembly rendering) incurs significant heap allocation overhead per iteration. Additionally, Capstone disassembly engine initialization is computationally expensive and should not be re-initialized on every disassembly request.
**Action:** Replace `format!` with `std::fmt::Write` and `write!` on pre-allocated strings (`String::with_capacity`) to avoid continuous allocations. Cache the Capstone instance inside the global `StealthApp` application state rather than creating a new one inside `disassemble_arm64`. Use import aliasing (`use std::fmt::Write as _;`) to avoid conflicts with `std::io::Write`.
