## 2024-05-18 - Expensive loop string allocations and Capstone init
**Learning:** In the eframe `egui` immediate mode GUI framework in Rust, creating strings in tight rendering loops using `format!` or string concatenations (`+` or `push_str` after `format!`) causes immense heap allocation overhead. In `gui/src/main.rs`, we are using string operations like `hex_str.push_str(&format!("{:02X} ", b));` repeatedly for every byte being rendered in a table every frame. Furthermore, `disassemble_arm64` initializes `Capstone` anew on every call, taking a lock and doing costly FFI setup. While `Capstone` doesn't implement `Send`, it's safe to store inside `StealthApp` since eframe's main app update loop only runs on the main UI thread.
**Action:** Use `std::fmt::Write` directly on pre-allocated strings (`String::with_capacity`) instead of `format!`. Store `Capstone` in `StealthApp` on initialization instead of creating it on demand.
