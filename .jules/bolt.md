## 2025-02-18 - Replacing format! with std::fmt::Write in Immediate Mode GUI Loops
**Learning:** In eframe/egui immediate-mode GUI apps, rendering functions are executed continuously (often 60+ FPS or triggered aggressively on interaction). The use of the `format!` macro within hot UI loops (like `draw_memory_panel` or `draw_debugger_panel`) leads to massive overhead due to continuous, per-iteration string heap allocations. The Rust compiler allows optimizing this by utilizing `std::fmt::Write` to append formatted string data to pre-allocated buffers (`String::with_capacity`), thereby drastically reducing heap allocation thrashing in hot loops without fundamentally altering the architecture.
**Action:** Always identify UI rendering loops or continuous data transformation hot paths. In Rust, refactor `format!` macros inside these loops to use `std::fmt::Write` macro (`write!`/`writeln!`) directly into pre-allocated string buffers.
