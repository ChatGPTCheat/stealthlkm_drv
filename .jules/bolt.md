## 2024-05-18 - Capstone Reinitialization
**Learning:** `Capstone::new()` is computationally expensive, especially in a tight rendering loop like `egui` where memory updates might be frequent or triggered often. The current implementation in `gui/src/main.rs` initializes a new `Capstone` instance on every `UiNotify::MemResult` which calls `disassemble_arm64`. The memory notes also confirm that `Capstone` is computationally expensive to initialize and is cached within the application state (e.g., `StealthApp` as `Option<Capstone>`). Note: `Capstone` does not implement the `Send` trait, but can be safely stored in `StealthApp` since `eframe::App` instances run on the main UI thread.
**Action:** Store the initialized `Capstone` instance in `StealthApp` state and reuse it across disassembly requests to prevent recreating it and reduce CPU usage / avoid performance bottleneck.
