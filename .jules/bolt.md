## 2024-06-10 - Capstone Re-initialization Bottleneck in egui Polling Loops
**Learning:** Initializing the `Capstone` disassembly engine inside a fast-polling UI or event loop (e.g., `process_net_events` when receiving memory chunks) creates a severe performance bottleneck. The engine setup is an expensive FFI operation, causing jank in `egui` interfaces and dropping the UI frame rate drastically. Since `Capstone` does not implement `Send` and cannot be easily passed around background threads, storing it directly in the `eframe::App` state on the main UI thread is both safe and necessary.
**Action:** Always cache expensive parser, disassembler, or FFI engine initializations as `Option<Engine>` inside the main `App` state for immediate-mode GUIs. Pass `&mut Engine` to helper functions instead of re-instantiating. Use `.ok()` to gracefully convert `Result` to `Option` during initialization to avoid panicking the entire application during startup if the engine fails to build.
