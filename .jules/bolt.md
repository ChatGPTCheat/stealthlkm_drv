## 2026-11-10 - [GUI Renderer Performance Optimization]
**Learning:** In eframe/egui immediate-mode UI loops, dynamically rebuilding large multi-line text representations (like hex dumps or disassembly logs) via repeated `format!` calls inside loops incurs massive overhead from continuous per-iteration string heap allocations. The `format!` macro creates a new string for every format argument combination, heavily lagging the GUI when processing data buffers frequently. Additionally, initializing the Capstone Engine in a hot code path (per disassembly call) is highly expensive.
**Action:** When building multi-line strings in hot loops (especially GUI rendering), preallocate strings using `String::with_capacity` and employ `std::fmt::Write` with the `write!` or `writeln!` macros to append data into the single buffer. Furthermore, computationally heavy structures like the Capstone disassembly engine should be initialized once at startup and cached in the global application state.
