## 2024-03-24 - [Avoid `format!` in hot loops and GUI rendering loops]
**Learning:** `format!` is expensive, doing heap allocations in a loop is a performance bottleneck. `std::fmt::Write` trait with `write!` macro allows writing directly into a pre-allocated string, saving memory allocations. In a GUI rendering loop executing every frame, this reduces massive overhead. Wait, in GUI rendering, we should avoid large loops doing this, but if we must format, `std::fmt::Write` is better. Note that `std::io::Write` and `std::fmt::Write` have naming collisions for their methods, so they should be imported correctly, or the trait can be brought into scope directly inside the blocks.
**Action:** Use `std::fmt::Write` instead of `format!` for string concatenations in hot paths, and alias trait imports to avoid collision if both `io::Write` and `fmt::Write` are needed.
