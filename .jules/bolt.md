## 2024-04-20 - Expensive Capstone Initialization in UI Thread
**Learning:** The `Capstone` disassembly engine is computationally expensive to initialize. Re-creating it on every memory read (e.g., in `disassemble_arm64`) causes significant main-thread latency and UI stuttering in the `eframe::egui` application. While `Capstone` doesn't implement `Send` and thus cannot be easily passed across channels or used in background threads without care, it is completely safe to cache it inside the `StealthApp` struct because `eframe::App` instances are bound to the main UI thread.
**Action:** Always cache the `Capstone` engine instance within the application state (`StealthApp`) during initialization and pass a reference to it for disassembly, rather than instantiating it per request.
