## 2024-05-24 - Immediate Mode UI Disassembly Bottleneck
**Learning:** In the Rust GUI component using `eframe::egui` (an immediate mode UI framework), computationally expensive initializations like the `Capstone` disassembly engine should not be placed inside event-handling routines (such as parsing `MemResult` network events) that might trigger on rapid UI poll loops. Repeatedly calling `Capstone::new()` caused significant performance overhead and lag because `egui` requests repaints constantly (e.g. `ctx.request_repaint_after(Duration::from_millis(50))`).
**Action:** Cache the `Capstone` instance by storing it within the primary `StealthApp` state during initialization (`StealthApp::new()`), wrapping it in an `Option<Capstone>` rather than using `.unwrap()`/`.expect()` to avoid panics. Reuse this cached instance across UI update cycles.
