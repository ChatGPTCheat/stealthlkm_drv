## 2024-05-23 - Capstone Initialization in UI Loops
**Learning:** Initializing the Capstone disassembly engine on demand within an application's event processing or UI polling loops is a significant performance bottleneck in the immediate mode GUI (`gui/src/main.rs`). The initialization process allocates resources and setups up the library state internally, adding latency to the main UI thread during network responses (`UiNotify::MemResult`), making the UI less responsive and blocking event loops that run very frequently (e.g., polling network queues at 50ms intervals).
**Action:** Always cache expensive library initializations (like Capstone) within the application's persistent state (e.g., `StealthApp` struct) during start-up, and pass a reference to the cached engine instead of repeatedly calling `Capstone::new()`.
