## 2024-07-28 - Optimized string formatting in Rust GUI UI loops
**Learning:** In the Rust GUI application (`gui/src/main.rs`) using `eframe`/`egui`, string generation using `format!` macro within the rendering loop or data iteration loop creates huge numbers of per-iteration string allocations. Since it iterates over memory chunks of 8 bytes for 1024 or more bytes, this caused extreme overhead and latency.
**Action:** Replace `format!` calls inside repetitive loops (e.g., rendering hex values or constructing assembly output) with `std::fmt::Write::write!` to pre-allocated `String` buffers (`String::with_capacity()`) to avoid repeated heap allocations and improve application rendering speed. When doing this alongside standard I/O writers (`std::io::Write`), ensure imports are aliased properly to prevent trait collisions (e.g., `use std::io::Write as IoWrite; use std::fmt::Write as FmtWrite;`).
