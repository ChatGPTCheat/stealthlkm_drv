## 2024-06-27 - [Optimization] Cache Capstone engine in egui
**Learning:** In immediate-mode GUI frameworks like `eframe::egui`, components and events are polled and redrawn at a high frequency (e.g., every 50ms). Instantiating heavy parsers or disassemblers like `Capstone` upon every memory read or event dispatch creates significant overhead and lag, particularly since `Capstone::new()` allocates new internal handles each time.
**Action:** When integrating heavy external C/C++ bindings (like Capstone, LLVM, etc) inside immediate-mode GUIs or polling networking loops, initialize the engine once in the application state constructor (e.g., `StealthApp::new()`) and pass references to it during the render/update cycle instead of recreating it per request. Ensure to handle `Result` types gracefully (e.g., using `.ok()` to store it in an `Option`) to avoid panics on application startup.
