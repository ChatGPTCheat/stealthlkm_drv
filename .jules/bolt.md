## 2024-05-18 - [Cache Capstone Initialization in UI Thread]
**Learning:** Initializing the `Capstone` disassembly engine (`Capstone::new().build()`) is a computationally expensive process. In the Rust GUI, it was being rebuilt on every memory read loop (or whenever memory bytes were interpreted as code) inside `disassemble_arm64`. While `Capstone` does not implement `Send` and cannot easily cross threads, the `eframe::App` instances run strictly on the main UI thread, meaning we can safely cache it as an `Option<Capstone>` inside the application state (`StealthApp`).
**Action:** Next time you see a heavy third-party parsing/disassembly library being initialized inside a frequent callback or update function in a GUI or tight loop, check if it can be initialized once and cached in the application's main state struct.
