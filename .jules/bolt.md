## 2024-05-24 - Capstone Engine Initialization Bottleneck
**Learning:** Initializing the `Capstone` disassembly engine (`Capstone::new()...build()`) is an expensive operation. Re-instantiating it on every memory read blocks the main UI thread in the `eframe::egui` immediate mode framework, leading to noticeable performance degradation. While `Capstone` doesn't implement `Send`, it is safe to cache in the application state since `eframe::App` instances run on the main UI thread.
**Action:** Cache expensive engine or parser instances (like `Capstone`) in the application state (e.g., `Option<Capstone>`) rather than re-creating them in event loops or data handlers. Use graceful error handling without `.unwrap()` or `.expect()` during initialization to prevent UI application panics.
